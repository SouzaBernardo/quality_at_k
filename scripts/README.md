# Scripts

Overview of the project scripts, organized by purpose.

---

## Orchestration

### `pipeline.py`
Project entry point. Runs two stages in sequence:
1. **PIPELINE** — 5 extraction and calculation scripts
2. **CHECKS** — 2 validation scripts

The pipeline exits with an error if any PIPELINE script fails. CHECKS run only
if the PIPELINE completes successfully.

```bash
python3 scripts/pipeline.py
```

---

## Main Pipeline

Scripts run in order by `pipeline.py`.

### `take_solution.py`
Reads raw ClassEval JSONs from `output/ClassEval_output/` and extracts the
Python code generated by each model. It removes Markdown fences and surrounding
prose, saves raw responses under `output/solutions/originals/{model}/`, and
saves sanitized versions under `output/solutions/{model}/`. It also creates
`output/results/pass_results.csv` with each task's functional status and
`pass_val`.

### `extract_sonar_metrics.py`
Connects to the SonarQube REST API (`http://localhost:9000`) and retrieves
project-level aggregate metrics (NCLOC, complexity, code smells, SQALE index,
etc.). Saves them to `output/results/raw/sonar_metrics.csv`.

### `extract_all_sonar_metrics_per_file.py`
Retrieves per-file metrics for all projects through the SonarQube API, using
pagination. Creates one CSV per project in
`output/results/raw/sonar_metrics_{project}_files.csv`.

### `merge_sonar_metrics.py`
Joins `pass_results.csv` with the per-file metric CSVs. For each task, it
calculates **Quality@1 (FQS)** using:

```
Quality@1(t) = Pass@1(t) × (1 − min(1, β × SQALE_Index(t) / NCLOC(t)))
```

where β = 0.1. Writes `output/results/combined_sonar_metrics.csv`.

### `aggregate_results.py`
Groups `combined_sonar_metrics.csv` by `(model, strategy, status)` and
calculates the mean `pass_val` and FQS. Writes
`output/results/aggregated_results.csv`.

## Validation

Scripts run after the pipeline by `pipeline.py`.

### `verify.py`
Post-pipeline checks:
- Each model has exactly 100 `.py` files
- No file contains Markdown contamination (fences or prose)
- All code is valid Python (no AST syntax errors)
- `combined_sonar_metrics.csv` and `pass_results.csv` are consistent

Prints a report to the console and exits with an error if any check fails.

### `generate_comparations.py`
Generates a side-by-side HTML diff for each model, comparing the original
(raw) code with the sanitized version. Saves reports to
`output/validation/comparation-{model}.html`.

## Utilities

Standalone scripts not run by `pipeline.py`.

### `compute_fqs.py`
Implements the Quality@1 formula as a pure function. It can be imported by
other scripts or run from the command line:

```bash
python3 scripts/compute_fqs.py --pass_val 1.0 --sqale 120 --ncloc 80
```

### `sort_csv.py`
Sorts any CSV by `(model, strategy, file)`, using the custom strategy order
H → C → I → GT. Used internally by `merge_sonar_metrics.py`.

### `test_fqs.py`
Unit tests for `compute_fqs`. Checks the formula against examples from the
thesis and edge cases (Pass@1 = 0, NCLOC = 0, and high or low technical debt).

```bash
python3 scripts/test_fqs.py
```

### `run_full_analysis.py`
Statistical analysis separate from the main pipeline. Reads a consolidated CSV
and generates:
- Mann–Whitney tests (RQ1: complexity in functional vs. non-functional code)
- Wilcoxon tests and Spearman correlation (RQ2: Pass@1 vs. Quality@1)
- 3 visualizations (bar plot, Pareto scatter plot, correlation heatmap)
- A Markdown report at `reports/statistical_report.md`

## SonarQube Infrastructure

SonarQube setup and maintenance scripts. Run them manually when needed.

### `run_sonar.sh`
Submits all projects to SonarQube using the `pysonar` scanner inside the
Compose `python` container. The script builds or updates the Python image
before scanning. Requires Docker Compose, a running SonarQube instance, and
tokens generated by `setup_sonar_projects.sh`. Copy `.env.windows` or
`.env.macos` to `.env` first so Compose selects the image for the host platform.

### `setup_sonar_projects.sh`
Creates projects that do not already exist and generates SonarQube analysis
tokens. Requires `curl` and `python3` (no `jq` dependency). Saves tokens to
`scripts/.sonar-tokens`, a Git-ignored local file accessible only to the
current user. Set `SONAR_AUTH` (`admin:password`) if authentication differs
from the default.

Run it again to recreate tokens if needed; revoke previous tokens in the
SonarQube interface.

### `delete_sonar_projects.sh`
Deletes all SonarQube projects. Useful for a complete reset.
