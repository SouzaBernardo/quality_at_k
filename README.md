# Quality@1

This repository contains a pipeline for evaluating generated Python solutions
from the [ClassEval](https://github.com/FudanSELab/ClassEval) benchmark. It
combines functional results from ClassEval with code-quality metrics collected
by SonarQube, then calculates and aggregates Quality@1 scores.

The current analysis uses the Holistic (`H`) generation strategy for GPT-4-Turbo,
GPT-3.5-Turbo, and WizardCoder-15B-V1.0, with ClassEval's GroundTruth solutions
as a reference group. These are the models and inputs configured by the
repository; the labels do not imply a performance ranking.

## Requirements and input data

- Docker with Docker Compose, running on the host
- The ClassEval input files in `output/ClassEval_output/`:
  - `model_output_v1.0.0/` with the model-output JSON files
  - `result/detailed_result.json` with the functional test results

The ClassEval input files are not generated by this repository. The SonarQube
service uses a preconfigured image that includes the analysis setup used for
this project.

## Run the full analysis

### 1. Select the SonarQube image for your machine

Copy the appropriate settings file to `.env` in the repository root. `.env` is
local and ignored by Git.

Windows (AMD64) or Intel Mac:

```powershell
Copy-Item .env.windows .env
```

Apple Silicon Mac:

```bash
cp .env.macos .env
```

### 2. Start SonarQube

```bash
docker compose up -d sonarqube
```

Wait for SonarQube to finish starting and become available at
[http://localhost:9000](http://localhost:9000).

### 3. Extract the solutions

This creates sanitized Python files under `output/solutions/`, which are used
as input for the SonarQube scan:

```bash
docker compose run --rm python scripts/take_solution.py
```

### 4. Create SonarQube projects and run the scan

The setup and scan scripts are Bash scripts. On Windows, run these commands
from WSL or Git Bash. The setup script uses the image's configured
administrator credentials by default; set `SONAR_AUTH` if they differ:

```bash
SONAR_AUTH='admin:<password>' ./scripts/setup_sonar_projects.sh
./scripts/run_sonar.sh
```

The setup script creates the four projects and saves their analysis tokens
locally in `scripts/.sonar-tokens`, which is ignored by Git. The scan submits
the extracted solutions to SonarQube.

### 5. Run the metrics pipeline

```bash
docker compose run --rm python scripts/pipeline.py
```

The pipeline runs these steps in order:

1. Extract and sanitize the model solutions and ClassEval functional results.
2. Retrieve aggregate and per-file metrics from SonarQube.
3. Join functional results with SonarQube metrics and calculate Quality@1.
4. Aggregate results by model, strategy, and functional status.
5. Validate generated files and metrics, then create HTML comparisons of raw
   and sanitized model outputs.

The Docker-based commands run the project scripts in the Compose Python
container. To run the pipeline directly on the host instead, use Python 3 and
install the packages listed in `requirements.txt`; SonarQube must still be
running and have completed the scan.

## Quality@1

For each task `t`, the pipeline calculates:

```text
Quality@1(t) = pass_value(t) × (1 − min(1, β × SQALE_Index(t) / NCLOC(t)))
```

Here, `β = 0.1`, `SQALE_Index` is SonarQube technical debt in minutes, and
`NCLOC` is the number of non-commented lines of code. `pass_value` comes from
ClassEval; it can be fractional for partial success. The pipeline assigns
GroundTruth a `pass_value` of `1.0` as a study assumption.

## Generated files

The pipeline writes its outputs under `output/`:

- `solutions/` — sanitized solutions and original model responses
- `results/pass_results.csv` — functional status and pass value per task
- `results/raw/` — aggregate and per-file SonarQube metrics
- `results/combined_sonar_metrics.csv` — task-level metrics and Quality@1
- `results/aggregated_results.csv` — averages grouped by model, strategy, and
  status
- `validation/` — HTML comparisons between original and sanitized solutions

For details about individual scripts, see [scripts/README.md](scripts/README.md).
